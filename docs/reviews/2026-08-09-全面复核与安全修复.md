# 事务所报告批量排版程序全面复核记录

## 复核结论

本轮已完成代码、运行、Word 结构和事务所排版业务规则的联合复核。修复后，在已覆盖的四川华信报告、财务报表附注和纯封面场景内，未发现仍会导致程序无法使用、覆盖原件或静默丢失复杂内容的致命问题。

Open XML SDK 报出的 schema 兼容性差异按使用要求只记警告、不阻断输出。正文缺失、页眉页脚关系损坏、业务门禁失败以及最终文件无法重新打开仍属于阻断项。

## 已修复问题

1. 删除不存在的窗口图标引用，解决程序启动时出现错误提示而主界面无法正常创建的问题。
2. 主程序、验证工具和测试项目统一迁移到 .NET 10，并更新 Open XML SDK 与 WPF-UI。
3. 输出先在同目录临时文件内完成处理和验证，成功后才生成正式输出名，避免用户把半成品误认为成功件。
4. 处理失败时不再删除失败件，改为保留 `_排版失败_时间戳.docx`，便于复核和定位。
5. 输出落盘后重新打开复核，防止保存或释放阶段出错却返回成功。
6. 三级标题只修改分隔符对应的文字节点，不再清空整个段落，保留超链接、书签等结构。
7. 注册会计师签字行含超链接、域、修订、公式或对象时不再清空重建。
8. 增加 `.docx` 输入输出、输出目录和防覆盖校验。
9. 表格普通数字继续使用千分位并保留两位小数；表头包含序号、编号、代码、号码、年份/年度等期间词或数量/人数/户数/件数/台数等数量词时，整列保持原始显示，不受所在列位置影响。
10. 批量处理跳过正式输出、失败件和遗留临时件，避免重复套格式。
11. 账号、账户和识别号类列加入数字格式豁免，防止银行账号、纳税人识别号被改成金额；`账户余额`仍按金额处理。
12. 修复封面与正文同处一个分节时整份文档无页码、正文表格被整体跳过的问题。
13. 保留表格自动编号、正文脚注引用样式，以及复杂签字行中的换行、隐藏文字和脚注引用。
14. 奇偶页不同的文档同时生成默认页脚和偶数页页脚；两行合并表头不再把第二行年度当金额。
15. 门禁新增复杂结构排版前后对比；文本框、脚注、尾注等数量减少或内容指纹变化时阻断输出。
16. 超过两位小数的数字舍入、未识别落款区会写入黄色复核日志。
17. 目录样式段落不再按正文标题重排；批量处理跳过 Word `~$` 锁文件、忽略无权限子目录，失败文件也会推进进度条。
18. 取消信号传入单文件流水线，并在分节、段落、表格和落款循环中检查。

## 业务规则复核

- 页面：A4，保留横向分节；正文及封面页边距与华信规则一致。
- 封面：支持自动识别、强制覆盖和纯封面只调页边距。
- 正文：大标题、文号、抬头、一至三级标题、普通正文的字体、字号、行距、缩进和段距一致。
- 表格：表头、边框、单元格行距、字符间距、数字格式及复杂结构保留策略一致；标识、账号、期间和数量类列按本轮要求豁免数字格式化，多行表头按表头区整体保护。
- 页眉页脚：封面节清理、正文已有页眉格式、页码域和有封面时正文从 1 起一致。
- 落款：事务所、城市、两名注册会计师和日期三边界识别，以及台阶缩进、签字留白和日期右对齐一致。

程序不替代 Word 或 WPS 的最终视觉检查。正式交付前仍应人工确认分页、跨页表格、签字盖章位置及客户特殊模板。宏、嵌入对象、复杂域和高度定制模板应先用脱敏副本单份试跑，再批量处理。
